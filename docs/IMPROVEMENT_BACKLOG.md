## 详细条目

### P0-1：补齐 Tauri 图标并恢复桌面构建

- **状态**：已完成（2026-10-04）。
- **问题描述**：`cargo check --offline` 在 `tauri-build` 阶段失败，因为 `src-tauri/icons/icon.ico` 不存在。
- **为什么是问题**：桌面应用无法完成 Rust 构建，之前“没有弹出窗口”的问题无法被可靠复现和验证。
- **用户影响**：用户无法启动或发布桌面应用；这是当前的可用性阻塞。
- **修改方案**：已补齐 SVG 源图标和 Tauri 生成的 PNG/ICO/ICNS 资源，更新 `tauri.conf.json` 的 bundle 图标配置，并重新执行 `cargo check`、`npm run tauri dev` 的启动 smoke test。
- **风险**：低；主要风险是资源格式或路径配置不匹配。
- **工作量**：小（Effort 2）。实际结果：Rust check 通过，开发窗口进程成功启动。

### P1-1：统一文件操作错误与状态反馈

- **问题描述**：Rust 侧返回 raw string，前端的 loading/error/success 处理分散；Sidebar 操作存在 fire-and-forget Promise。
- **为什么是问题**：权限、路径冲突、解析失败和 IO 失败无法给出不同的修复建议，也可能造成静默失败。
- **用户影响**：用户不知道保存或移动是否成功，失败后难以恢复。
- **修改方案**：定义稳定错误码/错误类型；在 store 统一 operation state；组件统一展示错误、重试和成功反馈，并等待所有文件操作 Promise。
- **风险**：中，需要同时调整 Rust command 与 TypeScript client/store。
- **工作量**：中（Effort 3）。

### P1-2：补齐文件操作和桌面关键流程测试

- **问题描述**：缺少 Rust 文件系统集成测试、Tauri smoke test 和核心 UI 流程 E2E。
- **为什么是问题**：原子写入、路径安全、回收站和未保存保护属于数据安全边界，仅靠当前前端单测不够。
- **用户影响**：回归可能导致数据丢失或桌面启动失败而不易发现。
- **修改方案**：为 `safe_relative`、扫描、写入、重命名、移动、删除和冲突策略添加临时目录测试；补充桌面/浏览器可区分的最小 smoke 流程。
- **风险**：中，需要稳定的测试夹具和 Tauri 运行环境。
- **工作量**：中偏大（Effort 4）。

### P1-3：收紧创建与文件移动的冲突保护

- **问题描述**：普通创建、模板创建和 capture 创建入口重复；`conflict` 请求未真正参与路径冲突决策；移动/重命名后的缓存和选中路径存在边界风险。
- **为什么是问题**：同名文件、根目录重命名、移动到自身/子目录等情况可能覆盖、丢失选择或产生陈旧索引。
- **用户影响**：笔记可能被覆盖或看起来“消失”。
- **修改方案**：统一创建用例和冲突策略（拒绝/改名/覆盖需显式选择），集中路径规范化，操作成功后原子更新 selection/cache/index。
- **风险**：中，需要保持现有 Vault 兼容。
- **工作量**：中（Effort 3）。

### P1-4：同步文档与真实实现

- **问题描述**：README、architecture、data-model、roadmap 仍描述 Foundation/demo 阶段，且 roadmap 存在重复阶段。
- **为什么是问题**：新贡献者会按错误的架构和功能边界工作，用户也无法判断当前能力。
- **用户影响**：安装、运行、贡献和排错成本上升。
- **修改方案**：在修复构建阻塞后同步 README、架构图、数据模型、路线图，并把验证命令和已知限制写入文档。
- **风险**：低。
- **工作量**：小（Effort 2）。

### P1-5：防止缺失 tags 导致编辑区白屏

- **状态**：已完成（2026-10-04）。
- **问题描述**：新建空白笔记没有 `tags` metadata，`PropertiesPanel` 直接对 `metadata.tags` 调用 `.map`，导致 React 渲染异常。
- **为什么是问题**：创建笔记或重新打开 Markdown 后，主界面可能出现白屏，用户无法继续编辑。
- **用户影响**：核心创建和打开流程不可用。
- **修改方案**：新增 `metadataTags` 归一化函数，缺少或非法 tags 时返回空数组，并添加回归单测。
- **风险**：低。
- **工作量**：小（Effort 1）。实际结果：`npm run typecheck`、`npm run test`、`npm run build` 均通过。

### P2-1：收敛 store、创建流程和快捷键边界

- **问题描述**：`vaultStore` 过度编排多个职责；TopBar 与 `useKeyboardShortcuts` 重复处理快捷键；旧 demo state 仍存在。
- **为什么是问题**：后续功能会继续增加耦合，行为可能因入口不同而不一致。
- **用户影响**：快捷键冲突、维护回归和新功能开发速度受影响。
- **修改方案**：先提炼少量明确的 use case/service 边界，统一快捷键注册，删除已确认无调用的 demo 状态。
- **风险**：中，需防止改变现有交互。
- **工作量**：中（Effort 3）。

### P2-2：提高 YAML 元数据兼容性

- **问题描述**：嵌套或混合 YAML 值会让整篇笔记解析失败，未知 frontmatter 结构也没有保留策略。
- **为什么是问题**：真实 Markdown Vault 往往来自其他工具，字段形状不一定只有当前 Primitive union。
- **用户影响**：用户可能无法打开已有笔记或保存后丢失元数据。
- **修改方案**：区分可编辑 metadata 与原始 frontmatter，至少在读取时保留未知字段并给出可见警告。
- **风险**：中高，涉及序列化兼容和数据完整性。
- **工作量**：较大（Effort 4）。

### P2-3：补齐空状态、反馈、确认和可访问性

- **进展**：本轮已完成弹窗关闭/ESC、New Note/Capture 视觉统一，以及 Rename/Move/Delete 的应用内上下文菜单和确认对话框；空状态、Toast、可访问性和快速创建入口仍待继续完善。
- **问题描述**：Inbox、索引失败、保存中、空 Vault、无搜索结果和文件操作确认不够完整，多个流程依赖 `window.prompt`。
- **为什么是问题**：桌面应用需要让用户知道当前状态和下一步动作，尤其是破坏性操作。
- **用户影响**：新用户容易迷失，失败和误操作成本较高。
- **修改方案**：统一 Dialog/Toast/inline error 组件，增加 loading/empty/error 状态，完善键盘焦点、label、ARIA 和响应式检查。
- **风险**：低到中。
- **工作量**：中（Effort 3）。

### P3-1：建立 CI、版本和发布基线

- **问题描述**：无 lint script、CI、安装包验证或版本策略。
- **为什么是问题**：提交质量和桌面发布无法持续验证。
- **用户影响**：回归可能在合并后才发现。
- **修改方案**：先定义 typecheck/test/build/cargo check 的 CI，随后接入 Tauri bundle 和版本发布检查。
- **风险**：中。
- **工作量**：较大（Effort 4）。

### P3-2：大 Vault 增量索引与监听

- **问题描述**：每次写入、移动和重命名都完整扫描并读取索引。
- **为什么是问题**：小 Vault 正常，但大目录会产生可感知延迟。
- **用户影响**：保存和导航变慢。
- **修改方案**：先测量实际瓶颈，再考虑 Tauri 文件监听、按路径增量更新和可取消任务。
- **风险**：高，涉及并发和一致性。
- **工作量**：很大（Effort 5）。

### P4-1：AI/RAG、云同步和账号

- **问题描述**：这些是潜在扩展，不是当前核心可用性问题。
- **为什么暂不处理**：会显著扩大数据模型、隐私、安全和产品范围。
- **用户影响**：当前阶段几乎没有直接收益，可能分散基础稳定性工作。
- **修改方案**：等本地 Vault、测试、发布和数据兼容达到 Beta 后再单独立项。
- **风险**：高。
- **工作量**：很大（Effort 5）。
